# Port knocking: клиент и сервер (knockd)

## Как стучит клиент

Для профиля со стуком перед подключением к серверу:

- **TCP-шаг**: одна попытка `connect()` на порт сервера. Ответа клиент не ждёт и обрывает попытку раньше,
  чем ядро повторило бы SYN (≤ 0,8 с). Так себя ведёт эталонный клиент `knock` из пакета knockd.
- **UDP-шаг**: одна датаграмма. Без указанных данных это один нулевой байт, как у `knock`. Данные можно
  задать hex-строкой: `1234/udp:68656c6c6f`.
- Шаги идут строго по очереди: следующий начинается только после того, как закончился предыдущий, и не
  раньше чем через «паузу между стуками».
- После последнего шага клиент ждёт ту же паузу (не меньше 150 мс), чтобы сервер успел добавить правило,
  и только потом подключается.
- Стук и подключение идут на один и тот же IP-адрес сервера и с одного адреса клиента.

Стучать заново клиент будет:

- перед новым подключением, если прошлый стук старше «Стучать повторно через»;
- после смены сети (Wi-Fi ↔ LTE), потому что у клиента сменился адрес;
- если подключение не удалось;
- один раз, если UDP-сессия после отправки данных не получает ответа дольше «Перестучать, если UDP-сессия
  без ответа». TCP так не отслеживается: установленное TCP-соединение переживает закрытие окна благодаря
  conntrack, а оборванное падает с ошибкой, и переподключение стучит само.

## Чем это отличается от `nc -z`

knockd засчитывает **любой** TCP-пакет на порт стука, если не задан `tcpflags`. Пакет на порт
последовательности, который не ожидается следующим, сбрасывает весь стук, в том числе повторный пакет
на предыдущий порт.

| | `knock` | `nc -z -w N` | этот клиент |
|---|---|---|---|
| пакетов на закрытый (DROP) порт | 1 SYN | SYN + повторы через 1 с, 3 с, … пока не истечёт `-w` | 1 SYN |
| пакетов на открытый порт | SYN, затем RST от ядра | полное рукопожатие + FIN | рукопожатие + FIN |
| порядок шагов | строгий | строгий, если вызывать по очереди | строгий |

Отсюда типичная поломка со скриптами на `nc -z`: при `-w 1` и больше ядро повторяет SYN на порт 1 уже
после стука в порт 2, knockd видит «не тот порт» и сбрасывает последовательность. Стук срабатывает через
раз, в зависимости от таймингов.

## Рекомендуемая настройка сервера

`/etc/knockd.conf`:

```ini
[options]
    UseSyslog

[proxy]
    sequence      = 7000,8000:udp,9000
    seq_timeout   = 10
    # считать только SYN: FIN/RST/ACK на порты стука (открытый порт, чужой трафик) не сбивают последовательность
    tcpflags      = syn
    start_command = /usr/sbin/nft add element inet filter knocked { %IP% timeout 30s }
```

Пояснения:

- **Порты стука должны быть закрыты** (DROP или REJECT) и не использоваться сервисами.
- **`tcpflags = syn`** обязателен, если среди портов стука есть открытые или через них ходит другой
  трафик. Повторные SYN это не спасает (у них тоже стоит SYN), поэтому важно, что клиент их не шлёт.
- **`seq_timeout`** должен быть больше `число шагов × пауза`. При 3 шагах и паузе 200 мс хватит и 5 с.
- **Окно доступа.** Удобнее всего nftables-set с таймаутом: адрес сам удаляется через 30 с, и
  `stop_command` не нужен. «Стучать повторно через» в профиле ставь **меньше** этого окна (по умолчанию
  10 с при окне 30 с). Тогда новые подключения не упрутся в уже закрытое окно.
- **Уже установленные соединения** должны жить после закрытия окна. Окно должно открывать только новые
  соединения, а установленные пропускаться по conntrack:

```nft
table inet filter {
    set knocked {
        type ipv4_addr
        flags timeout
    }
    chain input {
        type filter hook input priority 0; policy drop;
        ct state established,related accept
        iif lo accept
        # порт прокси: TCP для VLESS/Trojan/…, UDP для Hysteria2/TUIC/WireGuard
        ip saddr @knocked tcp dport 443 accept
        ip saddr @knocked udp dport 443 accept
        # … остальные правила (ssh и т.д.)
    }
}
```

Для IPv6 нужен свой set (`type ipv6_addr`) и `start_command_6`. Стук по IPv4 откроет порт только для
IPv4-адреса клиента.

Вариант на iptables по мотивам примера из документации knockd:

```ini
    start_command = /usr/sbin/iptables -I INPUT -s %IP% -p tcp --dport 443 -j ACCEPT
    cmd_timeout   = 30
    stop_command  = /usr/sbin/iptables -D INPUT -s %IP% -p tcp --dport 443 -j ACCEPT
```

Здесь тоже нужно правило `-m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT` раньше остальных.

## Протоколы поверх UDP

У Hysteria2, TUIC и WireGuard одна долгая UDP-сессия. Conntrack держит её, пока идёт трафик. Если сервер
перестал отвечать (перезагрузился, сбросил conntrack, закрыл окно), сработает «Перестучать, если UDP-сессия
без ответа». WireGuard без трафика может молчать долго, поэтому на клиенте стоит включить
`persistent_keepalive`, иначе conntrack на сервере истечёт. Сами keepalive-пакеты ответа не требуют и
повторный стук не вызывают.

Hysteria (v1) через плагин стук не поддерживает: плагин сам подключается к серверу в обход стука.

## Проверка

- На сервере: `knockd -D -i eth0` или журнал (`journalctl -u knockd`). Должна быть строка
  `OPEN SESAME` и, при ошибке, `sequence timeout` или сброс.
- `tcpdump -ni eth0 'port 7000 or port 8000 or port 9000'`: на каждый TCP-шаг ровно один SYN от
  клиента, без повторов.
- В логе клиента (уровень info): `knocking <ip> (3 steps)`. При повторном стуке по молчанию:
  `no reply from …, knocked again`, затем `answers again after re-knock` или `still no reply`.
- «Ping» профиля в списке (TCPing/ICMP) идёт мимо ядра и не стучит. Проверяй через URL-тест.

## Ограничения

- Стук виден в сети, и его можно повторить с того же адреса. Если нужна защита от повтора, это уже SPA
  (например, fwknop), а не port knocking.
- Если профиль со стуком стоит не первым в цепочке, стук идёт через предыдущий прокси. UDP-шаги сработают
  только если тот умеет UDP. Повторы SYN на стороне прокси клиент не контролирует.
